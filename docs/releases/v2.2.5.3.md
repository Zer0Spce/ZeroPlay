# ZeroPlay v2.2.5.3 — Live PPV Controls & Expanded Playback Sources

**Release date:** November 5, 2026  
**Platforms:** Android TV, Android mobile/tablet, Windows x64 (portable), and ZeroPlay web source-selection code  
**Release status:** Updated in place. The existing `v2.2.5.3` tag is unchanged; the latest Android APK assets replace earlier builds of the same public version.

This release combines the **Android Live PPV control improvements** with **five new movie and TV-series playback source choices** across supported platforms. The working Shaka Live PPV player from v2.2.5.2 is retained.

## Highlights

- **Auto-hiding Live PPV controls:** The top and bottom controls disappear after **4.5 seconds of uninterrupted playback** on Android TV and Android mobile/tablet.
- **Android TV remote navigation:** D-pad directions, Enter/OK, and Menu bring hidden controls back; the first remote press restores focus to Play/Pause instead of activating an invisible button. Explicit directional focus links cover the playback buttons and Back.
- **Visible when needed:** The controls remain visible while buffering, paused, displaying an error, or selecting a channel. Touching the video also reveals the controls.
- **Five more movie/series providers:** **VidRock, VidNest, VidRift, VidFast, and VidAPI** are now available as source choices.
- **Clearer unavailable-source label:** **VidSrc.sh** is displayed as **VidSrc [Offline]**. Its underlying source ID and saved per-title/default selections remain compatible.
- **One public version for desktop and Android:** Updated Android and Android TV APKs and a Windows x64 portable ZIP are provided under the existing `v2.2.5.3` release.

## Android TV & Android: Live PPV controls

The **Live PPV** tab continues to use the bundled **Shaka Player 5.2.12 in an Android WebView**, introduced in **v2.2.5.2**. This update changes the *player controls*, not the stream playback engine.

- Hide the player title/status bar and playback toolbar automatically once playback continues for 4.5 seconds.
- Show the toolbars when the user presses a remote navigation key or touches the screen.
- Restore TV remote focus and move between **Play/Pause, Live, Retry, Channels, Audio, Subtitles, Fit, and Back**.
- Keep controls accessible while playback is paused, loading, stalled, or showing errors.
- Preserve channel selection, retry behavior, Shaka error reporting, and the existing M3U playback path.
- Remove pending hide callbacks when leaving or destroying the player.

**Not changed:** Native **Live TV/IPTV**, **Live Sports**, Windows Live PPV playback, Android TV Home/navigation outside the Live PPV player, Movies/Series UI outside source selection, and **Audio Booster 2.0**. The protected stable backups were not modified.

## New movie & TV-series source options — all platforms

The following sources were added to the **Movies and Series playback source menus** on Android, Android TV, Windows, and the web codebase. They use provider-specific HTTPS embed URLs with TMDB movie IDs or TV season/episode IDs.

| Source | Playback domain | Notes |
| --- | --- | --- |
| **VidRock** | `vidrock.to` | Movie and episode embed option |
| **VidNest** | `vidnest.fun` | Movie and episode embed option |
| **VidRift** | `embed.vidrift.net` | Uses its `/embed/` movie/TV URL format |
| **VidFast** | `vidfast.vc` | Movie and episode embed option |
| **VidAPI** | `vaplayer.ru` | Embed player for the service documented at `vidapi.ru/api`; provider-side authorization may be required |

**Existing choices preserved:** VidStuck, ZXCStream (Beta), Embedwave (BETA), and the original `vidsrc-sh` source (now shown as **VidSrc [Offline]**). RawCast remains an optional, separately enabled source where supported.

Source selection was updated in the Android source picker, Android TV WebView movie/series routing and fallback, Windows settings and title-level selection, Windows provider recognition/recovery, and the website's settings and title-level selector.

**VidRift compatibility:** The website's embed iframe does **not** have an HTML `sandbox` attribute, as required by the provider. HTTPS origin checks, navigation restrictions, ad filtering, and browser/process security protections are still enforced; no browser security sandbox is disabled.

**Provider availability:** Source options generate URLs and apply the existing trusted-domain checks. Actual playback depends on each provider's server, supported content, region, CORS response, and any API-key/domain-whitelisting rules. In particular, VidAPI may require provider authorization. Adding a source does not guarantee that every title will play.
