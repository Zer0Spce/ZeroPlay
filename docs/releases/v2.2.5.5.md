# ZeroPlay v2.2.5.5 — Android TV Navigation Dropdowns & Windows Desktop Recovery

**Platforms updated:** Android TV and Windows x64 portable only.  
**Android mobile:** Not rebuilt or changed; stays on its prior release.  
**Protected:** Working Live PPV Shaka playback engine, Live TV/IPTV, Live Sports, existing stable backups and earlier tags.

## Android TV: one controller dropdown per movie/series source

The Settings → Player section now displays **each source on its own row**, with its controller mode selector immediately next to its name—no secondary pop-up menu.

Example layout:

| Source | Controller navigation |
| --- | --- |
| VidStuck | Smart / Hybrid (Default) ▾ |
| VidSrc [Offline] | Smart / Hybrid (Default) ▾ |
| Vidrock.to [Offline] | Smart / Hybrid (Default) ▾ |
| VidNest | Smart / Hybrid (Default) ▾ |
| VidRift | Smart / Hybrid (Default) ▾ |
| VidFast | Smart / Hybrid (Default) ▾ |
| VidAPI | Smart / Hybrid (Default) ▾ |

ZXCStream and Embedwave also appear with their own selectors, as do any other supported movie/series embed sources. RawCast is excluded because it uses a different playback mechanism.

Each dropdown has **Smart / Hybrid (Default)**, **D-pad**, and **Virtual Mouse**. Modes save immediately and independently per source. Every source defaults to Smart / Hybrid, even if an older release had a different global navigation setting. Existing saved per-source choices are respected; switching or recovering to another source loads that source's own mode.

The fixed Android TV Live PPV D-pad and OK button navigation from v2.2.5.4 remains unchanged and is separate from the movie/series provider settings. Shaka Player and streaming/network settings are unchanged.

## Windows: repair desktop interface and update detection

- **Fixed startup failure:** v2.2.5.4 packaging inserted a `publicVersion(...)` call without defining the function. The new release defines and calls a tested version helper, preventing the desktop UI state request from failing.
- **Fixed release-version handling:** The Windows package uses build-tool-safe `2.2.5-5` internally but correctly displays and compares **2.2.5.5**.
- **Fixed update loops:** The updater no longer treats the running release as older because of its internal numeric version suffix.
- **Fixed stale launcher selection:** A newly extracted 2.2.5.5 portable version will not automatically relaunch an older cached 2.2.5.4 executable.
- **Added packaged startup verification:** The Windows release build checks that the actual packaged desktop interface can initialize and return its public version.

No Windows player, Live PPV, live-channel, source-provider, or UI layout feature was intentionally changed beyond the version/startup repair.

### Installation

On Android TV, install the 2.2.5.5 TV APK over 2.2.5.4. Open **Settings → Player** to use the source rows.

On Windows, exit ZeroPlay and extract the 2.2.5.5 ZIP into your desired portable folder, replacing older program files if applicable while preserving your user-data folder. If an older cached version had been selected automatically, 2.2.5.5 now prefers the newer executable.

## Validation and limits

Release checks cover TV-only compilation, unit tests and signing, controller-dropdown regressions, Windows updater/version tests, Windows package startup verification, packaging and SHA-256 checksums. Automated checks cannot guarantee all third-party embed sites will play on every device.
